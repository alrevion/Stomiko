# @stomiko/db

Источник истины по схеме — **SQL-файлы в `sql/`**, а не ORM: `EXCLUDE`, RLS и plpgsql
в Drizzle невыразимы, а типы Supabase генерирует из самой БД. Второй источник истины
без выигрыша в рантайме не заводим — рантайм у нас `@supabase/supabase-js`.

Порядок применения:

| Файл | Что |
|---|---|
| `001_extensions_and_core.sql` | `btree_gist`, организация, филиалы, доступ, ресурсы, запись, приёмы |
| `002_catalog_and_stock.sql` | единицы, материалы, аналоги, партии, техкарты и блоки, услуги |
| `003_movements_and_costs.sql` | оказанные услуги, журнал движений, снимок себестоимости |
| `004_rls.sql` | RLS как защита в глубину |
| `005_move_btree_gist_out_of_public.sql` | вынос расширения из `public` (линтер Supabase) |
| `999_smoke.sql` | проверяет, что ограничения работают, а не просто созданы |

Проект: `pvtfksnhqdcodoyutfym` (Stomiko), регион `eu-central-1`, Postgres 17.6.

## Что схема гарантирует на уровне БД

- Один ресурс не может быть занят двумя приёмами одновременно (`EXCLUDE USING gist`).
  Отмена **удаляет** строки занятости — частичного предиката по статусу нет,
  поэтому отменённый приём слот не блокирует.
- Активный снимок себестоимости у приёма ровно один; предыдущие остаются
  с `superseded_at` — история себестоимости при reversal не теряется.
- `unpriced = (cost is null)`: ноль как заглушка невозможен на уровне схемы.
  Иначе неизвестная цена дала бы себестоимость 0 и маржу 100%.
- `shortfall` всегда без партии и всегда с состоянием `open|acknowledged`.
- Вложение блока в блок невозможно: строка блока ссылается только на материал
  или группу аналогов.
